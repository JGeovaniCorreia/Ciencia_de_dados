1 · Visão geral

Três peças, três responsabilidades

O sistema existe para que o trabalho com IA no projeto siga método e não perca contexto entre sessões. Cada peça responde a uma pergunta diferente, e nenhuma faz o trabalho das outras.

PeçaResponde aOnde está
Sistema multiagentes Quem trabalha em cada fase, em que ordem, e quando algo merece ser registrado. .claude/agents/ e .claude/CLAUDE.md deste projeto
Memória RAG O que já foi decidido, aprendido ou descartado em sessões anteriores. SQLite com sqlite-vec e um modelo de embeddings local
Protocolo MCP Como o Claude Code alcança a memória sem código sob medida. Servidor ml-context, processo local via stdio

O que é global e o que é deste projeto

O servidor MCP e a memória atendem todos os projetos do ambiente; os agentes, as skills e as instruções do projeto são o que cada projeto define para si. Para replicar o desenho em outro projeto, a parte global já está pronta e a parte do projeto é copiada e adaptada.

2 · Componente · Protocolo MCP

Um protocolo, não uma linguagem

MCP (Model Context Protocol) é um acordo sobre mensagens que padroniza como uma aplicação que hospeda um modelo conversa com capacidades externas. Reaproveita JSON-RPC 2.0 e define apenas quais mensagens valem e o que cada uma carrega. O problema que resolve é combinatório: sem um padrão, cada aplicação precisa de código sob medida para cada fonte de dados, N×M integrações; com ele, cada lado implementa o protocolo uma vez, N+M. O precedente direto é o LSP (Language Server Protocol), que fez o mesmo entre editores e linguagens.

A direção é vertical: um host ligado a várias capacidades. Comunicação entre agentes pares é outro problema, resolvido por outros protocolos, como o A2A.

As três primitivas, por quem decide usar

PrimitivaQuem decideO que éNo ml-context
Toolso modeloFunções com efeito: consultar, gravar, executar.As 5 ferramentas da seção 4.
Resourcesa aplicaçãoDados legíveis por URI: arquivos, registros, páginas.Não usa.
Promptso humanoTemplates de prompt reutilizáveis, expostos como slash commands.Não usa.

Há ainda o sampling, que inverte a direção: o servidor pede uma inferência ao modelo do cliente. Serve a um servidor que precisa de julgamento sem ter modelo próprio.

O que sustenta o desenho é a descoberta em tempo de execução. Ao conectar, o cliente pergunta o que existe e recebe nomes, descrições e JSON Schemas, sem que nenhum lado conheça o outro de antemão. Por isso um servidor escrito hoje funciona num host que ainda não existe. O custo é que a qualidade da integração passa a depender da descrição e do schema.

O modelo não fala MCP

O modelo emite a intenção de chamar uma ferramenta. O cliente traduz para JSON-RPC, aplica a política de permissão, executa e devolve o resultado como texto. É por isso que o Claude Code pode negar uma chamada sem que o servidor saiba que ela foi pedida, e é por isso que a allowlist de permissões (seção 6) funciona.

O protocolo não raciocina, não planeja e não guarda memória. Também não tem transporte próprio: roda sobre stdio, como aqui, ou sobre HTTP com streaming.

Onde termina a especificação e começa o código

Quem implementa o protocolo é o SDK oficial (pacote mcp). O código do servidor apenas registra funções e as deixa serem chamadas.

O acoplamento com o protocolo tem duas linhas. Os decorators registram a função; o SDK a invoca quando a mensagem correspondente chega pelo stdin: 

@server.list_tools()   # chamado ao receber tools/list
@server.call_tool()    # chamado ao receber tools/call

3 · Componente · Servidor ml-context

Arranque em segundo plano

O servidor é registrado no escopo de usuário, em ~/.claude.json, e por isso fica disponível em todos os projetos do ambiente. O cliente faz spawn de um .bat que prepara o ambiente antes de iniciar o Python: 

~/.claude.json  →  run_mcp.bat  →  python.exe  →  mcp_server.py
   registro           HF_HUB_OFFLINE=1            intérprete     stdio_server()
   (user scope)       TRANSFORMERS_OFFLINE=1
                      SSL_CERT_FILE= (limpa)

O cliente conta o tempo do handshake a partir do spawn. O limite padrão é 30 s; aqui está em 90 s, por MCP_TIMEOUT=90000 no ~/.claude/settings.json. A parte cara do arranque é o import sentence_transformers, que puxa o torch e o scipy, mais a carga do modelo. Nada disso roda antes do handshake: o import do módulo só carrega mcp e sqlite_vec, e o resto acontece em três peças. 

def get_model():                         # import + carga sob demanda,
    with _model_lock:                      # protegidos por lock
        if _model is None:
            from sentence_transformers import SentenceTransformer
            _model = SentenceTransformer(EMBEDDING_MODEL)
    return _model

def warm_up_model():                     # thread daemon disparada no main():
    get_model()                            # carrega enquanto o servidor já responde

def detach_stdin():                      # o SDK lê uma cópia do stdin;
    mcp_fd = os.dup(0)                     # o fd 0 do processo passa a ser NUL
    os.dup2(os.open(os.devnull, os.O_RDONLY), 0)
    return TextIOWrapper(os.fdopen(mcp_fd, "rb", buffering=0), encoding="utf-8")

Uma ferramenta chamada antes de o warm-up terminar espera pelo lock e recebe o modelo já carregado. Se a carga falhar, por exemplo com o modelo fora do cache, a ferramenta devolve o erro em texto e o servidor continua de pé: list_knowledge, que não usa vetor, segue respondendo.

Por que o stdin é desacoplado

O transporte stdio deixa uma leitura pendente no stdin entre as mensagens. No Windows, uma leitura síncrona pendente num pipe bloqueia as outras operações sobre o mesmo handle. Ao importar o sentence_transformers, a DLL de scipy.special consulta o stdin durante a inicialização e ficaria esperando a próxima mensagem do cliente.

Isso vale tanto para a thread de warm-up quanto para uma carga feita só na primeira ferramenta. detach_stdin() evita o bloqueio: o SDK lê uma cópia do handle e o stdin do processo aponta para NUL.

Decisão · arranque em segundo plano

Com o modelo carregado no import, o handshake levava cerca de 10 s com cache quente e passava dos 30 s logo após ligar o computador, deixando a sessão inteira sem memória. Mover a carga para depois do handshake elimina a dependência entre o tempo de arranque e o tamanho do modelo. O MCP_TIMEOUT de 90 s fica como rede de segurança: é um teto, e só custa tempo quando o servidor está quebrado.

4 · Componente · Memória RAG

Uma memória que o modelo lê e escreve

No RAG clássico, toda pergunta passa por uma busca antes de chegar ao modelo, sobre uma base de documentos fixa. Aqui o modelo decide quando buscar, chamando search_knowledge como qualquer outra ferramenta, e também grava: decisões e aprendizados de uma sessão viram contexto recuperável nas seguintes. É uma memória de longo prazo agêntica, e a regra de quando gravar fica na governança (seção 6).

O banco é um SQLite em ~/.ml-context/knowledge.db, fora de qualquer repositório, com a extensão sqlite-vec carregada em cada conexão. Os metadados vivem numa tabela relacional; os vetores, numa tabela virtual vec0. O id é o que costura as duas.

Os registros deste projeto ficam na partição price_prediction_california_housing: a decisão de alertar predições a partir de $450k, o diagnóstico do gap de erro na região Sul Costa, a descoberta de que o target truncado vale 5.000010 e não 5.0, os hiperparâmetros do XGBoost vencedor. É esse tipo de conteúdo que uma sessão nova recupera antes de propor algo que já foi testado ou descartado.

Gravação — save_knowledge

Busca — search_knowledge

Escolhas do índice vetorial

EscolhaPor quê
multilingual-e5-small A memória é escrita em português. Num benchmark de buscas parafraseadas, o modelo multilíngue levou o MRR de 0,39 (com o all-MiniLM-L6-v2, treinado em inglês) para 0,74, e aceita textos de até 512 tokens. Roda em CPU.
prefixos query / passage A família e5 foi treinada com prefixos distintos para pergunta e documento. Omitir os prefixos degrada a recuperação.
distance_metric=cosine É a métrica para a qual modelos de sentence embeddings são treinados. O padrão do vec0 é L2.
project como partition key Filtra por projeto dentro do KNN, sem depender de um overfetch de tamanho fixo que um projeto pequeno pode não alcançar.
Leitura da similaridade

As similaridades do e5 ficam comprimidas, em geral entre 0,8 e 0,9 no topo. O percentual exibido pela busca serve para ordenar resultados, não como limiar de relevância. Trocar o modelo exige recalcular todos os vetores, porque vetores de modelos diferentes vivem em espaços diferentes (seção 7).

As cinco ferramentas

FerramentaO que faz
save_knowledgeEmbeda e grava nas duas tabelas. Devolve o id.
search_knowledgeKNN cosseno + filtros + overfetch adaptativo.
list_knowledgeListagem cronológica de um projeto. Não usa o modelo, então responde mesmo se a carga dele falhar.
update_knowledgeAtualização parcial. Re-embeda só se título ou conteúdo mudaram; vec0 não aceita UPDATE, então recria a linha.
delete_knowledgeRemove das duas tabelas pelo id.

5 · Componente · Sistema multiagentes

Um time com papéis, fases e portões

Os agentes deste projeto são arquivos Markdown em .claude/agents/. Cada um define uma identidade, as especialidades, a fase do CRISP-DM em que atua, o formato da resposta, o viés que defende em debates e a regra de registro na memória. Um agente é, portanto, uma instrução de papel: o que separa o auditor do cientista é o que cada arquivo manda priorizar e questionar.

Os nove papéis

A divisão de modelos segue o tipo de trabalho: os papéis de julgamento amplo (negócio, decisão de debates e veredicto final) usam o modelo mais capaz; os de execução especializada usam o modelo intermediário.

O que é genérico e o que é do domínio

A maior parte de cada agente vale para qualquer projeto de ML: identidade, checklist, formato de resposta, viés em debates. Algumas regras são deste domínio, como o alerta de teto do engenheiro_mlops, que marca predições a partir de $450k porque o dataset truncou os valores acima de $500k. Ao replicar, essas regras são o que se troca.

Protocolo de debate

O coordenador abre um debate quando há mais de uma abordagem viável, quando a decisão pesa em custo, tempo ou desempenho, quando ela é difícil de reverter, ou quando o dono pede uma comparação. Participam ao menos dois agentes e o arquiteto:

  • Rodada 1: cada agente propõe uma solução de forma independente.
  • Rodada 2: cada agente critica a proposta do outro.
  • Rodada 3, se necessária: cada agente refina com base nas críticas.
  • Decisão: o arquiteto recebe o histórico completo e decide, ou devolve opções ranqueadas quando o trade-off é de negócio ou de preferência do dono.

Contexto em três níveis

Os agentes partem de instruções que o Claude Code carrega juntas no início da sessão, da mais geral para a mais específica. Cada nível complementa o anterior com o que só vale no seu escopo.

NívelArquivoConteúdo
Global~/.claude/CLAUDE.mdPreferências de comunicação e convenções de código válidas para qualquer projeto.
ÁreaCiencia_de_dados/CLAUDE.mdHardware, stack padrão, padrões de modelagem, validação, explicabilidade e fairness, e a lista de agentes.
Projeto.claude/CLAUDE.mdObjetivo de negócio (valor mediano por block group), dataset, métricas de sucesso (RMSE, MAE, R²), fairness geográfica, fase CRISP-DM e o histórico de decisões arquiteturais.

O projeto também tem skills em .claude/skills/: comandos reutilizáveis que os agentes acionam em vez de reescrever o mesmo código. Exemplos: /eda-report, /scoreboard, /optuna-status, /residuals-plot, /geo-plot e /serve-model.

6 · Governança

O que vira memória, e onde

Nenhum componente técnico decide quando gravar. Essa regra está nas instruções: consultar a memória com search_knowledge ao iniciar uma tarefa, e registrar ao tomar decisões e ao fechar uma fase do CRISP-DM. É o que converte um banco vetorial em disciplina de projeto.

O que aconteceuDestinoQuem registra
Decisão que muda a arquitetura ou a metodologia do projeto Banco e tabela de histórico de decisões do CLAUDE.md do projeto Agente que decidiu; o coordenador confere ao fechar a fase
Aprendizado técnico, padrão reutilizável, detalhe de experimento Só o banco Agente que aprendeu
Decisão de debate Banco, sempre arquiteto_solucoes
Veredicto do ciclo Banco, sempre chief_data_scientist
Padrão problemático recorrente no código Banco tech_lead
Finding pontual de revisão de código Não registra; fica no histórico do git —
Divisão de responsabilidades

O CLAUDE.md é a vitrine: versionado, legível por qualquer pessoa que abra o repositório, com as decisões que precisam ser públicas. O banco é o arquivo detalhado: local, buscável por significado, com o detalhe de experimento que não pertence a um README. Um registro só entra nos dois quando muda a arquitetura ou a metodologia do projeto.

Neste projeto, a escolha de RMSE, MAE e R² como métricas primárias e o alerta de teto em $450k estão nos dois lugares. Os hiperparâmetros do XGBoost e o diagnóstico do target truncado estão só no banco.

Permissões

A allowlist do settings.local.json do projeto libera search, save, list e delete sem confirmação. update_knowledge fica fora e pede confirmação a cada uso, porque reescreve um registro existente. Como o cliente aplica a permissão antes de falar com o servidor (seção 2), essa política não exige nenhum código no servidor.

7 · Operação

Verificação de saúde, backup e manutenção

O hook SessionStart roda o mcp_check.py no início de cada sessão e faz três checagens independentes, para que uma falha não esconda as outras. A principal repete o que o cliente faz: sobe o servidor pelo mesmo run_mcp.bat, envia initialize e mede a resposta.

Limite da sonda

O hook roda num processo próprio. Ele prova que o servidor consegue subir, mas não que a conexão daquela sessão do Claude Code deu certo, informação que o hook não recebe. Um servidor stdio atende apenas o processo que o iniciou; por isso rodar o .bat à mão serve para ver um erro, mas não conecta o Claude Code.

O backup é uma Scheduled Task horária que copia o banco para ~/iCloudDrive/Backups/ml-context, com 3 tentativas e retenção das 20 versões mais recentes. Ele compensa o banco viver fora do git.

Diagnóstico rápido

SintomaAção
Ferramentas mcp__ml-context__* ausentes na sessão/mcp → ml-context → Reconnect.
